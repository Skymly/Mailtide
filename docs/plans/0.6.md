# 0.6 Delete a Mailbox on an Account

## 产品句

The Person can delete a Mailbox on an Account.

**Shipped** on origin/main (`c35085d`, #179 / #181). No `v0.6.0` tag — tag cut stays human.

## Non-goals

- Nested hierarchy UI or Person-chosen IMAP delimiter
- Deleting Inbox / Sent / Drafts / Trash / Junk (roles stay provider-synced; those Mailboxes are rejected)
- Emptying a Mailbox first, or bulk delete
- Conversation / thread grouping in the UI (still Worth exploring)
- Gmail labels, Archive-as-All-Mail
- Entra, JMAP, macOS/iOS
- Android background sync, FCM, WorkManager
- Git tag / GitHub Release packing
- Avalonia control-tree tests
- Per-minor `ready-for-human` 回归票

## Vertical slice

One implement ticket (#179) crossing the layers that actually change:

1. IMAP port: delete a Mailbox by path.
2. Core: `DeleteMailboxAsync(accountId, mailboxId)` — IMAP delete first, then remove the local Mailbox (and its Messages). Reject missing Mailbox and role Mailboxes. IMAP failure leaves the local Mailbox unchanged.
3. BrowseShell + shared UI: Delete when a Mailbox is selected; reload Mailboxes.
4. Tests: Core + Desktop BrowseShell with the fake IMAP client. Live IMAP skipped unless a secret is already in the environment.

Use the existing Mailbox lifecycle ritual behind MailtideApp. No new public Core module that only forwards the verb.

## Scope

- [x] With a Mailbox selected, the Person can delete it; it disappears from that Account's Mailbox list.
- [x] Missing Mailbox, or a Mailbox with Inbox / Sent / Drafts / Trash / Junk role, is an error.
- [x] IMAP failure leaves the local Mailbox (and its Messages) unchanged.
