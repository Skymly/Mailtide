# 0.9 Move a Mailbox reply thread's Messages to another Mailbox

## 产品句

The Person can move a selected Mailbox reply thread's Messages into another Mailbox on the same Account.

**Shipped** on origin/main (`ac2a2a8`, #197 / #199). No `v0.9.0` tag — tag cut stays human.

## Non-goals

- Conversation as a stored domain container (Message stays the stored type)
- Nested Mailbox paths
- Bulk multi-select of arbitrary Messages
- Moving a Unified Inbox thread that spans Accounts
- Gmail labels, Archive-as-All-Mail
- Entra, JMAP, macOS/iOS
- Android background sync, FCM, WorkManager
- Git tag / GitHub Release packing
- Avalonia control-tree tests
- Per-minor `ready-for-human` 回归票

## Vertical slice

One implement ticket (#197) crossing the layers that actually change:

1. Core: given a Mailbox thread, move every Message in that reply chain to another Mailbox on the same Account. Reuse the 0.2 move ritual (IMAP then local MailboxId). `MailtideApp` stays the host-facing seam.
2. BrowseShell: when a Mailbox thread is selected, Move applies to the thread's Messages, not only one Selected Message.
3. Shared UI: reuse the 0.2 destination picker. Unified Inbox single-Message move is unchanged.
4. Tests: Core + Desktop BrowseShell with a seeded reply chain. Live IMAP skipped unless a secret is already in the environment.

No new public Core module that only forwards the verb.

## Scope

In:

- `MailtideApp` thread move at the existing move seam
- BrowseShell + MailShellView Move when a Mailbox thread is selected
- Desktop tests

Out:

- New public Conversation type or store table
- Nested Mailbox paths / arbitrary multi-select bulk move
- New public Core module that only forwards

## Acceptance

- [x] With a Mailbox reply thread selected, the Person can move that thread's Messages to another Mailbox on the same Account; they leave the current list and appear in the destination after reload.
- [x] A singleton thread (no Message-ID/References) still moves its one Message.
- [x] Unified Inbox single-Message move from 0.2 is unchanged.
- [x] IMAP failure leaves every Message in the thread where it was.
- [x] Core + BrowseShell tests green. `.\build.cmd Test` green on the implement PR.
