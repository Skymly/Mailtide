# 0.20 IMAP correctness, versioned store, and main surfaces

## 产品句

Mailtide can be a daily driver for a small personal install: IMAP UIDVALIDITY is honored, remote mail never falls back to cleartext, IMAP sessions are reused, the local store migrates by version, search does not load HTML into memory, and reading/compose occupy the main surface.

**Shipped** on `codex/0.2.0-foundations` toward GitHub `v0.2.0`.

## Non-goals

- New public Core module that only forwards MailtideApp verbs (ADR-0001)
- Relitigating ADR-0002 / ADR-0003
- Nested Mailbox paths, Gmail labels, CONDSTORE/QRESYNC
- Avalonia control-tree tests
- Cutting the GitHub tag from a machine without release secrets

## Vertical slice

1. Internal modules: `StoreMigrator`, `RemoteSnapshotSync`, `ReplyThreadIndex`, `OutboxStateMachine`, `ImapSessionPool`, `MailTls`, FTS `MessageSearchIndex`. `MailtideApp` stays the host-facing seam.
2. UIDVALIDITY change invalidates local RemoteIds for that Mailbox.
3. Forced TLS except loopback; command + IDLE session reuse.
4. MailShellView reading and compose as alternate main surfaces; click paths still go through BrowseShell / ComposeOutboxShell.
5. Tests: Core green including UIDVALIDITY, TLS policy, session reuse, legacy store upgrade, HTML search via FTS.

## Acceptance

- [x] Move / Trash / Restore and existing Person tests still pass.
- [x] UIDVALIDITY change refetches instead of treating new UIDs as the old Messages.
- [x] Remote ports never use `None` or `StartTlsWhenAvailable`.
- [x] Sequential SyncNow reuses one command IMAP session.
- [x] SchemaVersion is an integer; ALTER is gated by pragma, not empty catch.
- [x] Search does not `ToList` BodyHtml; HTML tokens still match via FTS.
- [x] BrowseShell still constructs with `MailtideApp` only.
