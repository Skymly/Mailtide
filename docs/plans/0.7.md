# 0.7 Browse Mailbox Messages grouped by reply thread

## 产品句

The Person can browse a Mailbox's Messages grouped by reply thread.

False on origin/main: `InternetMessageId` and `ReferencesJson` are stored, but BrowseShell lists Messages as a flat date-ordered list.

## Vertical slice

One implement ticket (hop D) crossing the layers that actually change:

1. Core: given a Mailbox, group its Messages by reply chain using stored `InternetMessageId` / `ReferencesJson`. A Message with no ids is its own group. `MailtideApp` stays the host-facing seam.
2. BrowseShell: when a Mailbox is selected, list groups (latest Message subject/from/date); select a group to list its Messages.
3. Shared UI: Mailbox message list shows groups; selecting a group shows the Messages. Unified Inbox stays flat.
4. Tests: Core + Desktop BrowseShell with seeded reply chains. Live IMAP skipped unless a secret is already in the environment.

No new public Core module that only forwards the verb.

## Scope

In:

- `MailtideApp` grouping at the existing list seam
- BrowseShell + MailShellView Mailbox list
- Desktop tests

Out:

- New public Conversation type or store table
- Unified Inbox grouping
- New public Core module that only forwards

## Acceptance

- [ ] With a Mailbox selected, Messages that share a reply chain appear as one group; the latest Message's subject/from/date is what the Person sees on the group row.
- [ ] Selecting a group lists its Messages. A Message with no Message-ID/References is a group of one.
- [ ] Unified Inbox listing is unchanged (still flat).
- [ ] Core + BrowseShell tests green. `.\build.cmd Test` green on the implement PR.
